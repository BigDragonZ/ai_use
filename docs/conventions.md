# 写作与整理规范

统一的规范让笔记长期可读、可检索、易于转成站点。

## 内容来源

- 笔记内容由 AI 在每轮对话学习结束后整理生成，**不手写**。
- 内容必须忠实于对话中实际学到的：讲过的概念、做过的练习、踩过的坑。
- 对话中没验证过的结论不写进"心得"，只能写进"待验证"。

## 文件命名

- 目录：`docs/notes/<主题 slug>/`，slug 用小写英文加连字符，如 `prompt-engineering`。
- 文件：`序号-标题.md`，序号两位数补零，如 `01-提示词的基本结构.md`。
- 一个主题一个目录，主题与路线图阶段对应。

## 笔记结构

每篇笔记必须使用 `templates/note-template.md` 的结构，包含：

1. **学习目标**：这篇笔记解决什么问题
2. **核心概念**：用自己的话总结，不照抄资料
3. **实践记录**：真实的提示词 / 代码 / 对话示例，附结果
4. **心得与坑**：踩过的坑、反直觉的发现
5. **复习清单**：3~5 个自测问题，用于日后回顾

## 写作原则

- **用自己的话写**：能讲清楚才是真的学会。
- **示例必须可复现**：提示词、代码、输入数据要完整，未来能重新跑一遍。
- **标注日期和工具版本**：AI 工具变化快，记录当时的模型/版本便于日后判断结论是否仍成立。
- **一篇一个主题**：一篇笔记只讲清楚一件事，长了就拆分。

## 格式约定

- 标题层级从 `#` 开始，不跳级。
- 代码块注明语言，如 ` ```python `。
- 外部资料用 Markdown 链接，注明来源名称。
- 图片放在同目录的 `assets/` 子目录，用相对路径引用。
